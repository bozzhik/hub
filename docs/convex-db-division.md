# Database Division (Convex)

The `/db` and `/db/[slug]` pages are a generated admin UI for Convex tables (CRUD + pagination).

## npm / bun scripts

Each Convex-related step has its **own** script; composites chain them.

| Script | Chain | Use when |
| --- | --- | --- |
| `db:gen` | — | Only regen UI meta + `convex/tables/*` base blocks from `convex/schema.ts`. |
| `convex:codegen` | — | Only refresh `convex/_generated/*` (types for `api.*`). |
| `convex:dev` | — | Local dev: push + watch. **Does not exit** until you stop the process. |
| `convex:once` | — | One push + codegen cycle, then **exit** (good for CI or “apply once”). |
| `db:sync` | `db:gen` → `convex:codegen` | After schema changes: local generated files + Convex types, **no** deploy. |
| `db:push` | `db:gen` → `convex:once` | After schema changes: regen table files, then **deploy once** to the dev deployment. |
| `db:dev` | `db:sync` → `convex:dev` | Full backend session: refresh everything, then start the watcher (**long-running**). |

Aliases: `convex` → `convex:dev`, `codegen` → `convex:codegen`.

**Typical terminals:** `bun dev` (Next.js) in one shell, `bun convex:dev` (or `bun convex`) in another.

**If the CLI looks stuck** on “Bundling component definitions…”: it may still be working; Convex also sometimes interacts badly with Bun’s install/runtime—try a clean install with npm, and avoid running **two** `convex` processes at once. See [convex-js#79](https://github.com/get-convex/convex-js/issues/79).

### After editing `convex/schema.ts`

```shell
bun db:sync
```

If you also need the dev deployment updated in one shot:

```shell
bun db:push
```

### Run & open

```shell
bun dev
```

- Open `/db?key=ACCESS_KEY` (protected by middleware in `src/proxy.ts`)
- Then use `/db/<table>` (e.g. `/db/demo`)

# Convex tables guide

## How to add a new table

1. Add a table to `convex/schema.ts` using `defineTable(...)` and validators from `convex/values` (`v.string()`, `v.number()`, etc).

2. Run:

```shell
bun db:sync
```

If `convex/tables/<table>.ts` did not exist yet, `db:gen` creates it with imports and a **generated-only** block. If the file already exists, add the markers below before re-running `db:gen`, `db:sync`, or `db:push`.

3. Open:

- `/db?key=ACCESS_KEY`
- `/db/<table>` (example: `/db/demo`)

## One file per table: `convex/tables/<table>.ts`

Everything for that collection lives in this file:

- **Inside** `// db-gen:base:start` … `// db-gen:base:end` — regenerated by `bun db:gen` (or any script that runs it, e.g. `db:sync`, `db:push`) whenever the schema changes. Do not edit by hand (it will be overwritten).
- **Outside** those markers — your own queries/mutations; the generator **never** changes that code.

If the markers are missing, `bun db:gen` will fail with an error telling you to add them or delete the file so it can be scaffolded.

Example markers:

```ts
// db-gen:base:start
export const list = query({ ... })
// ... getById, create, update, remove
// db-gen:base:end

export const myCustomQuery = query({ ... })
```

### Exports required for `/db` (inside the marked block)

These names and argument shapes must exist so `registry.generated.ts` and the UI can call them:

| export    | kind     | args                                                                        |
| --------- | -------- | --------------------------------------------------------------------------- |
| `length`  | query    | `{}` → `{ count, isTruncated }` (bounded to avoid unbounded reads)          |
| `list`    | query    | `{ paginationOpts }` → result of `.paginate(...)`                           |
| `getById` | query    | `{ id }` where `id` is `v.id("<table>")`                                    |
| `create`  | mutation | `{ doc }` — `doc` must match the table document shape (`v.object({ ... })`) |
| `update`  | mutation | `{ id, patch }` — `patch` has optional fields matching the table            |
| `remove`  | mutation | `{ id }`                                                                    |

Convex path: `convex/tables/demo.ts` → `api.tables.demo.*`.

### Generated client/runtime metadata

The `/db` pages also rely on these generated files:

- `src/lib/db/meta.generated.ts` — table/field metadata for building forms and columns.
- `src/lib/db/registry.generated.ts` — the allowlist of tables and mapping to `api.tables.<table>.*`.

After schema changes you MUST run:

```shell
bun db:sync
```

If you skip `db:gen`, `/db` meta and the base block will be stale. If you skip `convex:codegen` (or a command that runs it), `api.tables.*` types may be out of date.

## Access

`/db` is protected by the middleware in `src/proxy.ts`. First visit:

- `/db?key=ACCESS_KEY`

Set `ACCESS_KEY` in `.env.local`.
